# Security Policy

## Supported Versions

| Version | Supported |
|---|---|
| Latest release | Yes |
| Older releases | No |

Update this table when the project maintains more than one release line.

## Reporting a Vulnerability

**Do not report security vulnerabilities through public GitHub issues, pull requests or
discussions.**

Report them privately through GitHub private vulnerability reporting:
[Report a vulnerability](https://github.com/OWNER/REPOSITORY/security/advisories/new).

Maintainers must enable private vulnerability reporting in the repository settings
(**Security > Private vulnerability reporting**); GitHub offers it only for public repositories.
If the link above does not work, contact the maintainers listed in `.github/CODEOWNERS` privately
and ask for a secure channel before you share any details.

Please include:

- The affected component, version or commit.
- A description of the vulnerability and its possible impact.
- Steps to reproduce, ideally with a minimal proof of concept.
- Any known workaround or mitigation.

Do not include real credentials, personal data or production data in your report.

## Handling of Reports

- We acknowledge a report as soon as possible.
- Reports are handled confidentially and shared only with the people who need them to assess and
  fix the issue.
- We keep you informed about progress and agree on a disclosure date with you.

## Coordinated Disclosure

We publish details only after a fix or mitigation is available, through a GitHub security advisory
and the release notes. Please do not disclose the vulnerability publicly before then. With your
consent, we credit you in the advisory.
